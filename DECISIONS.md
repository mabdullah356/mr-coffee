# Implementation decisions

## Stack and structure

- The provided starter was a Vite React app, so the experience is built in that project rather than replacing its build system.
- React 19 renders the scenes; GSAP (`@gsap/react` + `ScrollTrigger`) drives scroll-linked and entrance motion; Lenis provides smooth scrolling and is driven by the GSAP ticker.
- `BRAND_NAME` lives in `src/config.js` and drives the footer wordmark and headline.
- Package installation works in this environment, so the project uses GSAP, Lenis and self-hosted `@fontsource` families instead of system fonts or CSS-only timelines.

## Artwork

- Decorative artwork is raster PNG/WebP generated locally with Pillow and NumPy (`scripts/generate-art.py`, `scripts/generate-assets.py`).
- The hero and product images use locally stored WebP photographs from Unsplash, under the Unsplash License. Their source IDs and direct URLs are listed in `ASSETS.md`.
- The nav, hero stamp and product-card arrows are separate transparent PNG icons generated by `scripts/generate-icons.py` and exported from `src/assets/index.js`.
- `npm run check:nosvg` enforces the no-SVG rule.

## Motion

- The preloader counts to 100 with direct DOM writes in `requestAnimationFrame` (no React state per frame). It starts the hero reveal when the exit begins, so the hero entrance plays while the panel slides away instead of after it.
- The hero pins `.hero-stage` itself (not an inner fixed-height element). Pinning an inner element inside a fixed-height stage previously created a pin spacer that overflowed without extending document flow, so the intro never became visible.
- The hero uses full-bleed hand-held matcha photography instead of the generated illustrated cups. Product panels and strawberry accents use real photographs; the generated leaf and berry doodles are no longer used.
- Hero, product and footer scroll timelines use `refreshPriority` so pin spacing is applied before later triggers are measured. Without it, `ScrollTrigger.refresh()` measured the intro/product/footer before the hero spacer existed and their start/end values were 1620px too early.
- Initial transforms are owned by GSAP rather than CSS. CSS starting transforms (e.g. `translateY(100%)`) were parsed as pixel values by GSAP and combined with `yPercent`, producing double offsets.
- Only `transform`, `opacity`, `clip-path` and `filter` are animated. Pointer parallax is rAF-coalesced and caches element rects, refreshing them on `ScrollTrigger` refresh/resize instead of reading layout on every pointer event.
- Nav solid state and active link are toggled directly on the DOM from a rAF scroll handler; no scroll state is stored in React.
- Custom cursor initialises only for fine pointers and uses `gsap.quickTo`; touch devices never mount the cursor logic.
- Product scroll pinning is desktop-only via `gsap.matchMedia`; below 1024px the cards stack and reveal individually.
- Reduced motion disables smooth scrolling, scroll pinning, parallax and entrance timelines; CSS shows the final states and hides the wave transition.

## Performance notes

- The production build (Vite preview, 1283x587 viewport) measured LCP ~3.4s and CLS 0.01 in a local Chromium trace. Most of the LCP delay is the intentional preloader + exit; the hero sky is the LCP image.
- Preloader minimum was reduced from 2.8s to 1.7s and the exit from 1.05s to 0.9s to shorten the time before the hero is visible.
- All 27 page images are preloaded before the counter completes, so there are no broken images or late layout changes after the reveal.
- The photographic assets are locally stored and compressed to WebP; the hero is 115 KB and the product photos are 36 KB and 61 KB.
